## SOP-1：每日常规运行流程

适用场景：日常批量处理店铺申诉，手动触发（未开启每日定时自动运行）。

### 1.1 开工前检查（B 页 + A 页）

- [ ] 打开软件，进入"店铺管理"（B 页）
- [ ] 逐一确认要处理的店铺"登录状态"列显示**已登录**（绿色）；显示"未登录"的先执行 **SOP-3：登录失效处理流程**
- [ ] 切到"总览仪表盘"（A 页），看一眼昨天的收尾情况：是否有"今日失败"数字异常偏高的店铺——如果有，先排查原因（多半是登录失效或网络问题），不要带着已知问题直接开新一轮

### 1.2 启动批量处理（C 页）

- [ ] 进入"运行控制"（C 页）
- [ ] 勾选今天要处理的店铺（默认全选；如果某家店铺临时不想处理，取消勾选）
- [ ] 确认"并发上限"数值符合预期（不确定就用默认值，不要临时调大——同时开的浏览器窗口越多，对电脑和网络的压力越大）
- [ ] 点击"启动"
- [ ] **真实提交确认框弹出时，逐条核对店铺清单是否就是本次要处理的那些**，确认无误再点确认——这是本流程里唯一的强制人工检查点，见 **SOP-5**
- [ ] 确认后不要立刻切走做别的事，先看 30 秒左右的运行日志，确认第一家店铺能正常打开浏览器、开始处理（排除"环境配置有问题、一启动就全部失败"这种情况）

### 1.3 运行中巡检

批量处理跑起来之后不需要一直盯着，但建议每隔一段时间（比如每小时）回来看一眼：

- [ ] C 页实时状态小表格：有没有店铺一直停在"启动失败"或"通信中断，已关闭"——如果有，记下店铺名，收工后按 **SOP-6** 排查
- [ ] 不需要处理"排队中"状态的店铺——这是正常排队，会被自动优先安排

### 1.4 收工检查（A 页 + F 页）

- [ ] 全部勾选的店铺处理完毕后（C 页状态回到空闲，或点了"优雅停止"确认停下来），切到 A 页看一眼今日汇总数字
- [ ] 有"今日失败"的店铺，去 F 页筛选这家店铺 + 今天，查看具体是哪些订单失败、失败原因是什么（明细表格 + 截图预览）
- [ ] 失败原因如果是"验证码 3 次都没识别成功"，属于正常范围，不需要处理，这些订单下一轮采集时如果还在可申诉状态会重新出现
- [ ] 失败原因如果是"登录失效"，去 B 页重新登录这家店铺，等下一轮自动重新处理；不需要手动干预具体订单
- [ ] 关闭软件前，确认 C 页状态是空闲的（没有"停止中…"字样），再关闭窗口

**别忘了**：今天提交的申诉，拼多多一般要 1-2 个工作日才出审核结果，不是当天能查到的——**过 1-2 天后**执行 **SOP-8** 查一下结果，不需要今天就做。

## SOP-2：新增店铺上线流程

适用场景：接入一家从未在本工具处理过的新店铺。

- [ ] B 页点"新增店铺"，填写便于识别的店铺名称（建议跟店铺后台显示的名字保持一致，方便以后对照）
- [ ] 点"开始登录"，在弹出的浏览器窗口里完成真实登录（扫码或账号密码），登录成功后软件会自动感知，不需要额外操作
- [ ] 确认 B 页列表里这家店铺"登录状态"显示"已登录"
- [ ] **首次试跑建议单独跑，不要跟其它已稳定运行的店铺一起混跑**：C 页只勾选这一家新店铺，点启动，用真实提交或先用较小的并发数观察，确认整套流程（采集→分析→填表→提交）在这家店铺上能正常走通
- [ ] 首次试跑完成后，去 F 页核对这家店铺当天的处理结果，确认状态和截图看起来正常
- [ ] 确认无误后，后续可以把这家店铺并入日常批次（**SOP-1**）一起处理

## SOP-3：登录失效处理流程

适用场景：B 页某家店铺显示"未登录"，或运行日志/A 页出现登录相关失败。

- [ ] B 页右键这家店铺 → "重新登录"
- [ ] 浏览器弹出后，在窗口里正常完成登录
- [ ] 登录成功后确认 B 页该店铺状态变回"已登录"
- [ ] **不需要手动处理这家店铺当天此前失败的订单**——重新登录成功后，下一轮批量处理会自动把这家店铺重新纳入待处理列表

---

## SOP-4：真实提交前安全检查点（每次点"启动"都要做）

真实提交不可撤回，这是整个流程里唯一强制要求人工确认的环节，**不能因为"之前确认过很多次了"而跳过检查**：

- [ ] 确认框里列出的店铺清单，跟你打算处理的店铺是同一批（防止手滑多勾/少勾了店铺）
- [ ] 确认这次开启的确实是"真实提交"而不是想先模拟验证效果（这个工具目前 C 页固定是真实提交模式，如果只是想验证新流程效果，应该先按 **SOP-2** 单独小范围试跑）
- [ ] 以上两条无误后再点确认；有任何不确定，先点取消，去核对清楚再重新启动

## SOP-5：软件关闭/停止流程

- **临时中断处理**：C 页点"优雅停止"，等状态变回空闲（不会打断正在处理中的订单，只是不再开始新的一单）
- **需要关闭软件**：直接关闭窗口即可，如果有任务在跑，软件会自动拦截并询问是否要先优雅停止——**选"仍然关闭"**，等它自动处理完再关，不要选强制关闭（除非等待超过 30 秒仍未停止，且确认没有更好的办法）
- **两种情况都不需要担心漏单**：没处理完的订单，下次重新跑这批店铺时会自动继续，不会漏、也不会重复提交已经交过的订单

---

## SOP-6：异常跳过订单复核流程

适用场景：F 页发现某订单状态是"失败"或跳过类状态，需要判断要不要人工介入。

| 失败/跳过原因 | 是否需要人工介入 | 处理方式 |
|---|---|---|
| 验证码 3 次识别失败 | 否 | 不用管，下一轮如果订单仍可申诉会自动重试 |
| 登录失效 | 是 | 执行 **SOP-3** |
| 已申诉/已超时/已驳回（跳过类） | 否 | 这类订单本身已经没有可操作的申诉入口，是正常的历史状态，不是本次运行的问题 |
| 通信中断/子进程异常退出 | 视情况 | 偶尔一次不用管，下一轮会重试；**同一家店铺连续多天出现**，上报技术支持 |
| 分析失败（AI 服务调用出错） | 视情况 | 偶尔一次不用管；**连续大量出现**，可能是网络或服务问题，上报技术支持 |
| 其它未列出的错误信息 | 是 | 截图 + 记录完整错误文案，上报技术支持 |

## SOP-7：每日定时自动运行的开启/调整流程

适用场景：希望软件在固定时间窗口内无人值守自动运行。

- [ ] 确认要长期挂机运行本工具的这台电脑不会在设定时间窗口内被关机/休眠，且软件窗口会一直保持打开（这不是系统级计划任务，软件没开着就不会触发）
- [ ] C 页勾选"启用每日自动运行"，设置开始/结束时间
- [ ] **首次打开时会弹一次性确认框**，仔细阅读文案后再确认（确认后以后每天到点会自动真实提交，不再逐次询问）
- [ ] 开启后仍建议按 **SOP-1 的 1.4 收工检查** 每天固定核对一次结果，不能因为"自动化了"就完全不看
- [ ] 需要调整时间窗口或临时关闭，随时可以在 C 页修改，修改本身不会弹确认框（弹确认框只发生在从"关"到"开"的那一次）

## SOP-8：查询申诉结果流程

适用场景：距离上一次提交申诉过去 1-2 个工作日之后，想知道审核结果（通过/驳回）。

- [ ] 进入"运行控制"（C 页）
- [ ] 勾选想查询的店铺（不需要跟当初提交时是同一批，比如只想查其中几家也可以）
- [ ] 点击"查询申诉结果"——**这是只读查询，不会提交/修改任何申诉，不需要像 SOP-4 那样做真实提交前检查**
- [ ] 等日志区显示查询全部完成的汇总提示
- [ ] 切到"报表/导出"（F 页），核对对应订单的状态是否已经更新（会自动同步，不需要手动点"刷新"）
- [ ] 查到"申诉未通过"的订单，视情况判断要不要走人工申诉或其它补救渠道（不在本工具处理范围内）
- [ ] 查了但状态没变化，是正常现象——说明拼多多那边还没审完，等 1-2 天再查一次即可，不需要频繁重复查询

**跟批量提交处理（SOP-1）的关系**：完全独立的一个动作，不需要绑在一起做，也不会互相影响数据；但两者不能同时跑（都要用同一批店铺的浏览器登录态），一边在跑时另一边的入口会被挡住，等它结束再操作即可。

## SOP-9：异常上报流程

出现以下情况，停止继续操作，联系技术支持并提供对应信息：

| 情况 | 需要提供的信息 |
|---|---|
| 软件无法启动/打开报错 | 报错截图、大概什么时候开始出现 |
| 提示"检测到已经有另一个调度进程在运行"，但确认没有重复打开 | 报错截图 |
| 某店铺连续 3 天以上无法登录成功 | 店铺名称、B 页截图 |
| 报表数据明显异常（数字对不上、导出文件打不开） | 具体是哪家店铺/哪个日期范围、截图 |
| 出现本 SOP 和《使用文档》都没提到的报错提示 | 完整报错文案截图 + 当时正在做什么操作 |

**上报前不要自行尝试"多点几次""删掉重装"之类的操作**，可能会掩盖问题原因，增加排查难度。
